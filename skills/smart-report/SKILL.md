# 智能报告生成（SmartReportGen）

依赖 MCP 服务 `smartreportgen`（Streamable HTTP，默认 `http://localhost:18600/mcp`）。
若工具不可用，提示用户先部署服务并为所用 agent 注册 MCP（见部署文档 `docs/DEPLOYMENT.md`「接入 Agent」），不要凭空编造数据。

本技能与 agent 无关（Claude Code、Codex、Cursor 等均可使用）。没有技能机制的 agent 可调用 MCP 工具 `get_skill_guide` 获取本文全文。

**认证与权限**：Codex CLI 可用 `codex mcp login smartreportgen` 通过浏览器登录海尔 IAM，并自动携带 IAM access token。使用 Bearer 配置的客户端可传入 海尔 IAM access token。工号决定可访问的场景和表。
- 检索、取表、探查、查询、校验、渲染都只覆盖**已授权**的场景与表；任何 SQL（含 JOIN / 子查询）引用未授权表都会被拒绝。
- 收到 `error_type: permission_denied` 时**不要改写 SQL 绕过**，直接告诉用户缺少哪张表/哪个场景的权限、应向管理员申请；可在已授权范围内给出降级方案（例如去掉依赖该表的章节）。
- 401 / 令牌无效或过期时，按客户端的认证方式重新登录或更新令牌。Codex CLI 使用 `codex mcp login smartreportgen`。
- 普通员工可以读取和修改本人创建的模板，并运行本人创建的结构化模板。分享权限决定能否查看或编辑报告各版本，数据查询仍按员工的数据权限执行。

每份新报告先将需求、已核实的数据证据、分析与展示设计整理为业务 Markdown 模板，保存到模板库。小节结论依据完整业务口径上的直接事实，明细样本用于理解字段。服务端 JSON 快照保存交互所需的完整查询结果。Agent 依据模板编写 HTML，预览验证后保存到报告库并关联模板版本。
最终回复给出需海尔 IAM 登录的报告链接、核心结论摘要和需要用户确认的口径假设。

## 执行契约（强制）

下列断言适用于新报告及修订版本，覆盖静态正文、指标卡、表格、图表（轴/标签/tooltip/图例）、JavaScript 和空态。首次编写 HTML 前必须读取 [展示契约与门禁](references/display-contract.md)；无本地文件时调用 `get_skill_guide(reference="display-contract")`。

| ID | 可判定断言 | 检查依据 |
|---|---|---|
| R-01 冲突裁决 | 低优先级条目、历史报告和 Agent 判断不得为高优先级规则开例外；Agent 只能在列明的可裁量范围内决定 | d 节的生效规则表，逐项记录来源和裁决 |
| R-02 事实直取 | 不补算业务值；无直接事实则不展示该业务数值 | 查询、`tables_used`、快照和逐值证据 |
| R-03 证据完整 | 每项定量结论能定位同口径的具体事实行；样本不支持总体结论 | b 节逐表/逐分析项清单 |
| R-04 粒度一致 | 各筛选组合只选择对应直接事实，总体与明细分别读取 | 默认、组合筛选及重置对账 |
| R-05 缺失与尺度 | 真零保留；空值、重复事实或未知比例尺度显示 `—`，清除旧颜色和判断 | 边界夹具与实际页面 |
| R-06 离线交付 | HTML 内嵌全部资源和快照；打开及筛选不访问接口或相邻文件 | 静态门禁和离线浏览器检查 |
| R-07 数字格式 | 按生效规则统一符号、单位和精度。启用 `percent-only` 时，率值与源端率差全篇仅用 `%`，禁止 `pp`、`百分点`、`pct`，无展示路径例外 | 展示契约、禁用词扫描、六类落地面复核 |
| R-08 单一入口 | 动态数字只调用统一 `fmtNum` / `fmtPct` / `fmtDelta`；状态只调用 `metricState` / `applyMetric` / `stateColor`，不得另写局部格式化或配色逻辑 | 固定格式化模块及应用脚本扫描 |
| R-09 状态一致 | 同一指标和状态在正文、卡片、表格及图表中使用同一语义 class 与色值；原始值判断，显示值不参与判断 | 指标→条件→class→色值映射及边界验证 |
| R-10 保存门禁 | 源文档静态审计、展开后审计及六类落地面/边界行为复核全部通过，才可 `save_report` / `revise_report`；修改文件后旧审计失效 | `assets/audit_report.py` 退出码为 0，审计记录绑定文件 SHA-256 |

R-07 的 `percent-only` 由当前用户或场景的生效要求启用，不能把示例自动变成所有场景的业务定义。未禁用率差符号时使用 `semantic` 模式，仍须确认率差语义及尺度。符号约定不改变源端事实；不得把“率差”改称“相对增幅”，也不得自行做减法。详见展示契约中的正反例。

## 内置事实与交付规则

**业务指标必须直取已确认事实表或正式视图；缺失不补算。** 实际、目标、同期、完成率、同比、差额、贡献、总计、整体比率与预测均须有直接字段或正式指标行。不能在 SQL、Python、前端、图表或 LLM 中用 SUM、AVG、相除、相减等补出业务值，也不能用自建计算视图绕过规则。历史公式不构成当前计算授权。

允许不产生新业务值的筛选、透视、排序、已确认别名映射、明确单位换算、绘图坐标和同口径比较。真实零与负号保留，空值不转零；重复事实核实唯一键及版本，不能随意取首条。MTD/YTD、总体/国内/海外及父子层级分别直取。缺失值显示 `—`/“暂无数据”，源端完成率与显示金额不一致时也不能自行改算。比例尺度和单位不明时待确认，不凭数值大小推断。

每个展示值须保留来源表、字段/指标编码、组织、期间、口径、区域、层级、查询批次、原始值及单位，并能定位具体事实行。原因须有字段或业务材料支持，建议与事实分开。详细规则与压力场景见 [取数与结论规则](references/fact-contract.md)，无本地文件时调用 `get_skill_guide(reference="fact-contract")`。

**最终报告为可独立离线打开的单文件 HTML。** CSS、JavaScript、所用图表运行时（包括 ECharts）、图表配置及快照全部内嵌；禁止外部资源、CDN、动态加载和相邻文件依赖。打开、浏览和筛选不得触发取数、生成或保存。

这些要求不参与视觉样式的优先级覆盖。例外须由用户另行明确变更业务口径，并在模板及报告中留痕。数据访问仍只走 MCP，遵循当前任务或会话授权及 IAM 权限；新数据源未授权时先说明用途、范围并确认，既有授权无需重复申请。附件的历史授权和验证声明不能充当本次授权或验证。

仅在用户明确要求复现绿能九月基准时，按需读取 [绿能2026年9月场景参考](references/green-energy-september-facts.md)，或调用 `get_skill_guide(reference="green-energy-september-facts")`。固定组织、账期和批次不作为其他报告的默认值；附件未附 HTML/CSS，不能声称完成样式复现。

## a. 解析需求，锁定业务场景

1. 先从用户需求中提炼：**分析对象、时间范围、关注维度、关注指标、对比方式（同比/环比/目标）、受众**。缺失项不必追问，采用合理默认并在最终回复中说明。
2. 调用 `search_business_scenarios(query=用户原话, top_k=3)`。
   - 取第 1 名；若返回 `tip` 提示相关度接近或偏低，阅读各候选的 business_description 判断，仍无法确定时**向用户确认**再继续。
   - 无命中：可能是业务术语不同，也可能是**没有该场景权限**（检索只覆盖已授权场景）。换术语重试一次，仍无则告知用户并停止。
3. 调用 `get_dataset_tables(dataset_id)` 获取场景的分析思路（`analysis_approach`）、**你有权限的**表或视图、各表取值范围（`row_filters`）及数据源类型（决定 SQL 方言：postgresql / mysql / starrocks / oracle / api=DuckDB）。场景取数自动应用这些条件；把影响分析口径的范围写进报告。
   若返回 `unauthorized_table_count > 0`，说明还有表无权访问：只用已授权的表设计报告，并在最终回复中说明哪些分析因权限受限未覆盖。

## b. 探查数据，确定分析目标与报告结构

**先探查，后设计；结论必须来自查询结果，禁止编造数字。**

1. 把场景的 `analysis_approach` 作为探查和设计的重要依据。结合用户关注的问题，确定先查哪些指标、对比哪些对象、验证哪些假设。若场景未填写分析思路，就从用户需求与实际数据出发。
2. **先逐表核实可用指标。** 用 `describe_tables` 获取授权表清单和字段，按 `next_offset` 翻完所有页。依次处理每张表或视图，先用 `describe_table` 核实字段、数据粒度、主键或候选关联键、时间和维度范围及缺失情况，再用只引用该表的直接事实查询核实指标、口径、单位及有效覆盖范围。例如分别核实实绩表的销量与目标表的目标量。记录每张表提供的直接指标及其具体事实行。确实无关或无法使用的表，记录原因及对分析的影响。前几行样本用于核对字段和行结构，总体结论由对应范围的正式总计或总体指标支持。
3. **逐小节获取全量口径的结论证据。** 将场景的 `analysis_approach` 和用户问题拆为可验证的分析项。为每个有数据结论的小节明确统计期间、适用范围、指标定义、排除条件和对比基准。通过 `run_query` 查询该口径的直接事实及正式总计行，并记录查询、`tables_used`、覆盖期、缺失状态和关键数值的行级证据。跨表仅在核实关联键、基数、未匹配记录及共同粒度后关联原值，禁止关联放大或自行聚合产生业务指标。行数等技术元数据不充当经营事实。
   - `sample_rows` 只用于检查字段和值的形状。确认事实查询的结果完整，检查 `truncated`、SQL 自带的行数限制、筛选范围、缺失与重复。使用分页接口时，核验是否覆盖所需页次或使用有完整性保证的正式指标接口。
   - 排名展示须覆盖全部可比对象再排序选取 Top N，技术排序不冒充上游正式排名；集中度、贡献和整体基数必须直取正式指标。比较描述要有对应基准，归因结论要有分解或验证证据。每项标明「证据齐全」或「有缺口」，写明缺失的表、字段、期间、权限与影响。证据不足时，仅描述可核实的范围及其局限。
4. **按筛选能力准备可对账的快照。** 对每组数据用 `run_query(snapshot=true, sample_rows=5)` 保存查询结果，记录 `snapshot_id`、列、行数、来源表、覆盖范围和用途。快照包含 SQL 返回的全部结果，仍须用第 3 步的直接事实核对它覆盖了结论所需范围。有样本结构后可把 `sample_rows` 设为 0；快照有效期为 24 小时。
   - 每个可选筛选口径均需保存对应的直接事实，包括同比、达成率、占比、去重人数、中位数及正式总计。不能按筛选后的明细求和、平均或相除补齐。缺少该口径时显示缺数，或明确该小节使用固定口径。
   - `truncated=true` 时未创建快照。优先缩小到所需正式指标与字段，必要时用互不重叠且覆盖完整口径的范围分批，并对照源端正式总计核实关键指标；禁止为减少行数自行聚合。`truncated=false` 只说明服务端返回上限未截断 SQL 结果。

## c. 全局筛选与联动

- 按受众会切换的分析口径选择筛选器。用同一份筛选状态选择图表与结论所用的直接事实，覆盖页面初始加载、筛选切换及重置。不同查询的筛选字段需要映射时显式处理，目标粒度无法支持某些筛选时注明适用范围。
- 结论中受筛选影响的数字、排名、贡献和判断，均与卡片使用同一份已对账的数据和筛选状态。同比与达成率使用该筛选口径的源端直接字段；全部范围使用正式总计或整体指标，不能用明细求和或平均比率。同一次刷新更新数字、颜色和对应的达标或升降描述。
- 同比按原始数值判定，正值用 `color-trend-up`（默认绿），负值用 `color-trend-down`（默认红），零为中性色。达成率达到或超过业务阈值用达标色（默认绿），低于阈值用未达标色（默认红）。只按用户或场景已确认的阈值分类，且必须先确认源比率尺度；缺阈值时展示已确认尺度的原值而不分类，尺度未知时显示 `—`，内部保留原始值待确认。用未舍入数值比较，按展示精度格式化。用正负号、涨跌或达标文字补充颜色含义。
- 空结果、源字段缺失、比例尺度未知或对应事实不唯一时，显示 `—` 并清除该指标之前的颜色及状态。静态结论数字若只适用于某个固定口径，须标明该口径。
- **执行 R-08/R-09**：把上面的状态条件登记为唯一映射，所有页面部位及桥图/瀑布图复用。中性辅助柱可用中性色；带有升降/达标语义的柱、标签和 tooltip 不能另选分类色。不要在章节内复制判断或拼接符号。

## d. 样式设计

**执行 R-01**：事实、权限与离线约束独立于样式。展示要求的生效顺序为 **当前用户明确要求 > 业务场景规则 > 通用规则 > 内置展示默认值**。同类别使用工具返回的条目顺序确定层内优先级。用户明确变更业务口径时仍按事实规则留痕，不由样式条目推定授权。

Agent 的可裁量范围限于：章节安排、图表类型、筛选维度，以及未被生效规则指定的布局、字体、间距和装饰色。数字格式、单位、比例尺度、事实口径、缺失处理和已指定的状态色不可自行放宽。规则适用性不明确时先核实范围；可以同时满足时取更严格的约束并在回复中说明；互斥或口径不明时保留缺数或暂停受影响项，不能自选豁免。

1. 调用 `get_style_rules(business_scenario, query=用户需求)`，同时取得独立的 `reporting_rules` 和 `specified`——业务场景规则（当前用户本人为该场景配置的）
   ≥ 通用规则（管理员配置的）≥ 内置样式 按优先级合并的约束：
   - `specified.theme` 提供视觉样式取值，编写 HTML 时将适用取值落实到 CSS 和图表配置。需要沿用内置版式时，可直接内联工具返回的 `builtin_style.css`，并参考 `builtin_style.components` 组织页面。
   - `specified.items`：展示要求（好坏判定 / 涨跌颜色 / 数字格式 / 文案要求 / 其他展示要求），各类别内业务场景规则的条目排在前面，同类冲突时以排在前面的为准。
   - 同类卡片跨章节复用组件样式及图表基础配置。排序、单位、轴范围及数据着色按业务含义设置。
   - 章节安排、图表类型和筛选条件在 b、c 节决定。样式条目中涉及这些分析决策的文字不作为展示约束。
2. 将适用条目编成**生效规则表**：`ID | 来源及优先级 | 断言 | 适用面 | 允许模式（没有则写无）| 检查方法 | 冲突裁决`。外部条目无 ID 时按类别赋予稳定 ID（如 `U-NUM-01`），保留原文和来源。只将规则明确列出的例外登记为允许模式，不可自行增加。
   当前用户明确要求“红涨绿跌”等变更时，记录它替代的展示条目并统一落实。内置的“源端率差可用 pp”只是未禁用时的默认许可，不能豁免生效的“全篇仅用 %”。在最终回复的“口径与假设”说明实际裁决；不能以“已说明”为理由违反断言。
3. 仅在上述可裁量范围内决定未指定的视觉样式。结论正文的状态颜色要与页面底色保持足够对比度；不能以可读性为由自行改变已指定的状态语义，需调整背景或明暗时仍保持生效规则。

## d 与 e 之间. 编写并保存业务报告模板

1. 用业务人员能读懂的 Markdown 整理 a–d 的结果。写清报告用途、受众和业务问题。多表场景保留逐表指标清单（来源表、粒度、指标、覆盖范围、限制）。逐小节记录结论、全量口径的直接事实查询、原始值及行级证据、数据覆盖和缺口，以及证据与快照的对账结果。按章节记录展示方式、默认筛选范围、联动和结论颜色规则。为每张数据卡片记录使用的快照、实际返回的直接字段或指标编码、原始单位及比例尺度、适用筛选及预期的缺数表现。必须附上 d 节生效规则表、展示契约 JSON、统一格式化入口、指标状态映射和六类落地面清单；不适用项写原因，不可略去。
2. 用 `save_report_template(name, markdown=全文, template_type="business", dataset_id, user_requirement, analysis_goal, business_summary)` 保存。完整文档放在 `markdown`，`business_summary` 只填一段用于模板列表的用途说明。用普通 Markdown 标题、段落、列表和表格表达，数据查询仍通过 MCP 执行。
3. 保存成功后，用 `get_report_template(template_id, version=返回的版本号)` 读取该版本，作为下一步的开发依据。后续如果发现口径或设计需要变更，先更新该模板并取得新版本，再依据该版本开发。

## e. 编写、验证和保存单文件 HTML

**保存前硬门禁（R-07–R-10）**：按 [展示契约与门禁](references/display-contract.md) 内联 `assets/report-formatters.js` 原文，执行 `assets/audit_report.py`。先审计含引用源文档，再预览并审计展开文件；命中禁用词、第二套格式化逻辑或未完成复核即阻断保存。不能以浏览器“看起来正确”替代脚本，也不能以脚本通过替代离线、筛选、颜色和事实核对。文件一经修改，重跑源审计、预览及展开后审计。

1. 根据已保存版本的业务模板，编写包含 `<!doctype html>`、`<html>`、`<head>` 和 `<body>` 的完整文档，内联 CSS、JavaScript、必要的图表库和图像。每份查询结果写一个空数据标签 `<script type="application/json" id="srg-data-sales" data-srg-snapshot="实际返回的 snapshot_id"></script>`。将数据标签放在读取它们的脚本之前，确保数据块的 `id` 在整个文档中唯一。服务端将完整的 `{columns, rows}` 写进对应标签。页面读取前确认节点为预期的 JSON 脚本，按 `columns` 对应行数组的字段，以 MCP 实际返回的列名为准。绑定失败时，为受影响的卡片显示可定位到快照或字段的错误状态，按数据覆盖情况显示明确的空结果或缺数说明。页面运行时不需要访问 JSON 文件、CDN 或接口，动态文案使用 `textContent` 等文本 API。
2. 调用 `preview_report_html(html=含快照引用的完整文档)`，用返回的 `url` 在浏览器预览，或用 `download_url` 下载展开后的 HTML，再以离线方式打开。默认筛选和有数据的代表性筛选下，逐小节将页面结论的数字、排名和判断与同口径的 `run_query` 直接事实和正式总计对账。快照与核数查询因数据更新而出现差异时，按同一数据时点复核并刷新相应快照和结论。按模板清单逐卡检查指标值、表格行、图表系列及点数。检查浏览器运行错误；有数据的卡片出现空壳、占位符或错误时，应修复并重新预览后再保存。在桌面和窄屏分别检查卡片行是否等高并铺满可用宽度。切换每个筛选维度，检查多条件组合及重置，核对图表、指标卡、表格和结论是否按适用范围一起更新。至少验证同比为正、负、零，达成率高于、低于、刚好达到阈值，以及空结果、缺失比率、真实零和重复事实时的文案、符号和实际颜色。正式数据缺少边界样本时可用明确标注的独立夹具验证选择、格式化及着色，正式报告只使用已核实的直接事实。下载后的 HTML 在离线环境中应无子资源请求，筛选或重置不访问任何接口。
   在报告实际展示容器中检查宽屏和窄屏：页面符合所采用的版式、整页无横向溢出，目录链接定位到对应章节。对照不同章节中的同类卡片，检查表格排版与同类图表样式在初始和筛选状态下一致。
3. 逐项填写展示契约中的六类落地面清单和边界复核记录，运行展开后审计，确认退出码为 0。任一失败先修复并从源审计重新开始；工具或浏览器不可用时说明未完成的门禁，不能保存或声称验证通过。**仅在 R-10 通过后**调用 `save_report(name, html=审计记录绑定且预览时提交的含引用文档, template_id, template_version)`。服务端保存展开后的离线单文件，报告版本不依赖临时 JSON 的有效期。传入实际用于开发的模板 ID 和版本，并用返回的 `url` 和 `download_url` 交付报告。创建人和管理员可在报告库按员工工号分享，接收人使用海尔 IAM 登录。

服务端的 `validate_report_template` 和 `render_report_html` 用于维护和运行已有的结构化模板。

## f. 修改已有报告

1. 用已有报告链接或 `list_reports(keyword=...)` 定位 `report_id`。候选不明确时，用标题、来源模板和当前版本让用户确认。`list_report_versions(report_id)` 可查看版本、基准版本和修改说明。
2. 调用 `get_report(report_id, include_html=true, omit_snapshot_data=true)` 读取该员工选中的版本，未选择时读取最新版。用户指定版本或给出带 `?version=` 的链接时，显式传入 `version`。用户要求切换默认版本时调用 `select_report_version(report_id, version)`，省略 `version` 可恢复跟随最新版。
3. 以返回的 `revision` 锁定本次修改的基准。有模板读取权限时，用该报告返回的 `template_id` 和 `template_version` 读取对应版本的模板。仅修改文字、样式或交互时，保留 `data-srg-snapshot="base"` 的空标签和对应 `id`，服务端从基准版本复用数据。刷新或更改数据时，用 `run_query(snapshot=true)` 重新取数，换成新快照 ID。旧报告中手工内联的数据会随原有 HTML 返回。
4. 任何存量报告在本次被修订或展示规则变更后，都要按当前契约重跑完整格式审计；不继承旧版本的“已验证”声明。只重构展示入口并保留数据引用，不擅自刷新事实或批量改写历史版本。按 e 节通过全部门禁，预览时传 `report_id` 和 `base_version=读取的 revision`。调用 `revise_report(report_id, name, base_version=读取的 revision, html=审计记录绑定且预览时提交的文档)`，可用 `change_note` 记录改动。保存会分配新版本号并保留历史。用户从 v2 修改已有 v1–v4 的报告，结果是基于 v2 的 v5。
5. 回复中给出实际基准版本、新版本号、改动摘要和返回的固定版本链接。

## 最终回复格式

```
已生成报告：<标题>
- 报告链接：<url>（离线单文件：<download_url>）
- 报告：#<report_id> v<version>，业务场景：<场景>
- 业务模板：#<template_id> v<template_version>（在报告模板库查看）
- 核心结论：摘要，附支持结论的关键数字
- 口径与假设：时间范围、同比口径、未覆盖的维度/数据缺口、展示规则裁决与用户明确变更依据
- 权限说明（如有）：因无权访问而未纳入的表/分析
```
