# 智能报告生成

业务人员通过自然语言提交需求、审阅预览和提出修改。业务数据统一通过 `smartreportgen` MCP 获取，权限由海尔 IAM 和系统授权确认。遇到 `permission_denied`，说明缺少的权限及其对分析的影响。

## 1. 按需求选择路线

### 修改已有报告

1. 有报告链接或 ID 时直接读取。否则用 `list_reports(keyword=...)` 查找与需求匹配的可访问报告。唯一明确候选直接使用。多个候选都符合需求时列出名称、当前版本和链接，请用户确认后开始修改。
2. 调用 `get_report(report_id, version, include_source=true)`。用户指定版本时显式传入，省略时读取该员工已选版本或最新版。记下实际返回的 `revision` 作为 `base_version`。需要模板时使用 `get_report_template(template_id, report_id, report_version)`。
3. 纯样式或换图直接进入第 3 步，基准快照已有所需事实时复用原数据。改期间、指标、粒度或数据范围时回到第 2 步核实受影响的取数和绑定。历史自编 HTML 可用 `preview_report_html` 查看静态诊断。迁移后走正式发布。

### 新建报告

1. 用原始需求调用 `search_business_scenarios`。按业务对象、分析口径和数据范围判断是否匹配已有授权场景。已有适用场景就直接引用并进入第 2 步。用户已经明确指定场景时核对其授权并复用。
2. **只有找不到适用场景时才进入「构建业务场景」分支。** 可换场景名称或业务术语再检索一次。若已知场景存在但当前员工缺少访问权，引导申请授权。否则用工具返回的 `scenario_management_url` 引导普通用户打开「业务场景 → 新建业务场景」。
3. 用户选择管理员已经配置并向本人或角色开放的数据源及所需表或视图，填写业务描述、分析思路和附加筛选。数据源固定的行范围持续生效。场景保存后返回新建报告流程，从第 2 步开始设计。缺少可引用数据源时，联系管理员配置数据源或开放所需表。

### 按模板重跑

确认模板版本和新账期，复用第 2 步的设计，再按新参数同批取数并走第 3 至 5 步。

## 2. 根据分析思路、表元数据和样式设计模板

1. **先读分析思路。** 调用 `get_dataset_tables` 获取分析思路、授权表、固定行范围及已登记的 `semantic_metrics`。以分析思路组织报告问题、章节和指标。多表场景用 `describe_tables(include_profile=true)` 分页查看字段和轻量画像。按表核实指标、覆盖范围、粒度与关联键，已有画像直接复用。需要全表统计时才调用 `describe_table(mode="full")`。
2. **确认事实和联动。** 上游已有正式汇总值时，优先按期间、组织等维度筛选、直取所需字段，例如总体值、目标、同比和完成率。缺少预聚合口径时，使用场景负责人登记且允许当前分组的官方公式。用 `run_query` 核实字段、值域、唯一性及实际引用的 `tables_used`。多个正式快照用 `query_report_data` 一次按同批次获取。单组直取可用 `run_query(snapshot=true, sample_rows=200)`。样本行数与查询总行数一致、未受样本或查询行数上限限制，且来源覆盖完整时，直接用该次结果核数。当前筛选缺少同口径唯一事实时，相关结论、数字和状态一起显示缺数。结构化正文用 `{{metric}}`，自由版式正文用 `<srg-val>` 绑定数字。
3. **取得生效样式。** 用 `get_style_rules(..., include_css=false)` 获取样式与规则，按当前用户明确要求、场景规则、通用规则、内置默认的优先级应用。用 `format` 声明精度、单位、比例尺度和判定阈值。按需求配置主题、卡片、图例、状态色等展示选项。
4. **保存设计结果。** 按需求选模板。标准卡片和图表用 `get_report_spec`、`save_report_spec`。需要自定义版式、按模块拼装或更细的 ECharts 视觉时，用 `get_free_report_spec`、`save_free_report_template`，保存页面骨架、分模块 HTML/CSS 和受管数据槽位。两类模板都保存取数计划、字段绑定、筛选联动和展示规则。使用返回的 `template_id` 与版本进入第 3 步。用 `business_summary` 记录用途和重要口径，有未覆盖的分析项或权限限制时在交付中说明。

## 3. 基于模板多轮拼装 HTML，按模块调整

- **先搭骨架，再补各块。** 模型按需求安排结论、指标卡、图表和表格。每轮聚焦受影响的章节或卡片，保持同一筛选口径与数据绑定。业务人员通过对话提出修改，模型负责更新内部模板定义。
- **结构化模板。** 按章节和卡片调整 `spec`。报告纯样式调整可在结构化预览传 `theme_overrides`。
- **自由版式模板。** 先建页面骨架、模块和全局绑定。每轮只通过 `patch_free_report_template(template_id, expected_version, modules)` 提交受影响的已有模块。增删模块、改全局 CSS 或更换受控取数计划时保存完整模板。按返回的新版本继续迭代。冲突时先读取最新版本再合入当前模块。正文和卡片数字由 `<srg-val m="指标引用">` 注入，图表和表格由 `<srg-output m="模块内输出引用">` 注入。原生 ECharts 声明式视觉选项由服务端验证，数据、标签格式和状态由内置运行时提供。[自由版式契约](references/free-report.md)
- **复用事实。** 新报告已有同批快照时预览传 `bindings`。纯展示修订传 `report_id` 和实际读取的 `base_version`，预览省略 `bindings` 与 `parameters`。新账期传 `parameters` 同批重取。增加基准中未投影的字段时按当前权限重新取数。
- **换图示例。** 同口径期初、期末和各项增减额已在基准快照时，可以只把图表模块的输出换成瀑布图并复用数据。期初期末用灰色放首尾，上涨用绿色放左、标签在下，下降用红色放右、标签在上。

## 4. 正式发布前验收

结构化模板调用 `preview_report_spec`，自由版式调用 `preview_free_report`。新建时可填模板 ID 和版本，修订时填 `report_id` 和修订分支锁定的 `base_version`。服务端检查字段与数据范围，审计源和展开后的 HTML，并用 Chromium 核对正文、卡片、表格、图表、筛选与重置、状态颜色、桌面和窄屏、离线运行。业务归因和有歧义的口径仍需根据证据核实。验收发现问题时回到相应环节修正，重新预览。通过 `get_preview_file(preview_id, offset, chars)` 可以在已登录的 MCP 通道分页读取正式预览。

## 5. 锁定验收结果并保存版本

- 保存第 4 步验收通过的 `preview_id`。新发布用 `save_report(name, preview_id)`。修订用 `revise_report(report_id, name, base_version, preview_id)` 追加版本。协作时可用 `expected_version` 检查最新版本是否已变化。内容修改后重新验收，使用新的预览 ID。
- 交付报告 ID、版本、固定链接、离线下载链接、主要结论和口径缺口。分享前，接收人须已登记并拥有该版本的来源数据权限。读取和下载时复核当前授权。

## 补充优化

- **快**。优先复用业务场景、模板、批量画像和快照。监测首个可审阅预览耗时、纯样式修订耗时及重复取数次数。
- **准**。跟踪定量结论能否追溯到来源、筛选变更后的对账结果，以及缺数和零是否正确区分。
- **稳**。跟踪首次验收通过率、协作版本冲突和保存失败。自由模板支持模块级更新，所有正式发布执行整页验收。
